# Кейс 4. Запись к мастеру

Авито Услуги: клиент записывается к мастеру на свободный слот.
Слот может быть занят - это нормальная ситуация, а не ошибка сервера.

Сущность Booking:
- id (integer)
- masterName (string)
- slot (string) - например "2026-09-20 14:00"
- status (string) - confirmed / cancelled

## Чекпоинт 1 (руками в main.go)
GET /bookings/{id} - вернуть JSON брони: id из пути, остальное любое.

## Чекпоинт 2 (через спеку)
POST /bookings - тело с masterName и slot, ответ 201 с созданной Booking
(status - confirmed). Схемы Booking и BookingCreate опишите в components
по образцу Item/ItemCreate.

## Чекпоинт 3 (раскладка ручек, без кода)
Операции: записаться, посмотреть свою запись, список свободных слотов мастера,
отменить запись.
Для каждой: метод + путь + статус ответа.

Спорный вопрос к финалу: слот уже занят - какой статус вернуть на попытку
записи? (подсказка: это не 400 и не 500). И перенос записи на другой слот -
это PATCH или отмена + новая запись?
